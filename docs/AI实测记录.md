## 实测中遇到的问题

- 开发调试时浏览器将读取的密钥脱敏成占位文字，导致一次 401。用户在网页重新填写后连接成功。
- 表单中的模型名称一度变为非模型标识，导致一次 503（上游没有对应模型提供商）。重新填写模型名称后连接成功。
- 开发热更新中断过一次尚未采纳的知识库预览，最终重新生成并采纳；中断结果没有写入待办。
- 日期控件使用原生设置方式并通过其他表单字段触发重新渲染复核，避免仅改变可见值却未提交到表单状态。

## 数据库写入说明与 SQL

本次没有新增表、索引、约束或迁移。示例通过现有业务接口写入本地体验账号的数据，数据库文件不提交。完整表结构、索引及约束见 [server/schema.sql](../server/schema.sql)。

- `goals` 保存目标、用户外键、固定截止日期、验收说明、公开性及可选赠品；`id` 为主键，`user_id` 引用 `users(id)`；名称 2～100 字符、公开性 0/1，状态及资源类型有枚举约束。沿用用户和创建时间、状态和截止日、公开性索引。三个新增目标均为 `is_public=0`，赠品标题为空。
- `tasks` 保存目标外键、标题、日期、分钟数、完成时间和顺序；`id` 为主键，`goal_id` 引用 `goals(id)` 并级联删除；标题 1～150 字符，分钟数 1～480；沿用 `(goal_id,date,position)` 和 `done_at` 索引。

创建目标和采纳计划使用现有参数化语句，语义如下：

```sql
INSERT INTO goals (id, user_id, title, description, deadline, created_at,
                   is_public, stake_title, stake_type, stake_detail)
VALUES (?, ?, ?, ?, ?, ?, 0, '', 'vps', '');

-- 每个计划独立事务提交，保留该目标已完成的任务。
BEGIN IMMEDIATE;
DELETE FROM tasks
WHERE goal_id = ? AND date >= ? AND done_at IS NULL;
INSERT INTO tasks (id, goal_id, title, date, minutes, position)
VALUES (?, ?, ?, ?, ?, ?);
-- 对本轮计划中的每一项执行 INSERT，再统一提交。
COMMIT;
```

采纳逻辑按契约归属授权；本次均为新示例目标，因此 DELETE 没有删除已有任务。示例没有申报失败、生成赠送活动或修改其他用户数据。
